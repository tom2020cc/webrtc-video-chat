# 🚀 WebRTC视频聊天室 - 新功能使用指南（完整版）

## 🎯 概述

本指南详细介绍了WebRTC视频聊天室的所有新增功能，包括WhatsApp集成、管理员权限系统、聊天室增强功能等。

---

## 📱 WhatsApp集成功能

### 设置WhatsApp信息

1. **点击WhatsApp按钮**
   - 在聊天室标题栏找到 📱 按钮
   - 点击按钮打开WhatsApp设置弹窗

2. **填写联系信息**
   ```
   WhatsApp号码：+86 138 0000 0000
   显示名称：您的名字
   ```

3. **保存信息**
   - 点击"保存"按钮
   - 系统会自动将您的WhatsApp信息保存到个人资料中

### 分享WhatsApp信息

1. **在房间内分享**
   - 确保已加入房间
   - 点击 📱 按钮分享您的WhatsApp信息
   - 房间内所有用户都会看到您的联系信息

2. **查看他人分享的信息**
   - 其他用户分享的WhatsApp信息会显示在聊天区域
   - 信息包括：显示名称、WhatsApp号码

### 一键WhatsApp聊天

1. **接收分享信息**
   - 当其他用户分享WhatsApp信息时
   - 聊天区域会显示绿色卡片样式的分享信息

2. **一键发起对话**
   - 点击"💬 一键聊天"按钮
   - 自动打开WhatsApp与对方对话
   - 无需手动复制号码

### 使用场景

- **商务沟通**：快速分享WhatsApp商务联系方式
- **社交联系**：让朋友通过WhatsApp联系您
- **客户服务**：客户可以直接通过WhatsApp与客服沟通

## 🔐 管理员权限系统

### 管理员登录

1. **访问管理员登录**
   - 点击聊天室标题栏的 🔐 按钮
   - 输入管理员密码

2. **登录成功**
   - 按钮变为 👑 管理员 样式
   - 获得管理员权限（会话时长有限制）

### 管理员功能

#### 清除房间
```javascript
// 服务器端示例（需要在前端实现UI）
socket.emit('admin-clear-room', {
  roomId: '房间号',
  token: adminToken,
  reason: '违规内容清理'
});
```

**权限说明**：
- 只有管理员可以清除房间
- 清除房间会删除所有聊天记录
- 所有成员会被强制移出房间
- 操作会被记录到管理员日志

#### 查看管理员日志
```javascript
socket.emit('admin-get-logs', {
  token: adminToken,
  limit: 50
});
```

### 安全特性

- **IP限制**：只允许特定IP地址登录管理员
- **会话时效**：管理员会话有固定时长，过期需要重新登录
- **操作审计**：所有管理员操作都会被记录
- **令牌验证**：每次管理员操作都需要验证令牌

## 💬 聊天室增强功能

### 消息回复

1. **回复消息**
   - 将鼠标悬停在消息上（自己的消息）
   - 点击 ↩️ 回复按钮
   - 输入框会显示回复状态和原消息内容

2. **回复消息显示**
   ```
   ↩️ 回复 张三: 这是原消息的内容...
   您的回复内容
   ```

### 消息删除

1. **删除自己的消息**
   - 将鼠标悬停在消息上（自己的消息）
   - 点击 🗑️ 删除按钮
   - 确认删除

2. **管理员删除**
   - 管理员可以删除任何消息
   - 删除操作会记录在管理员日志中

### 消息转发

1. **转发消息到其他房间**
   ```javascript
   socket.emit('forwardMessage', {
     sourceRoomId: '原房间',
     messageId: '消息ID',
     targetRoomId: '目标房间'
   });
   ```

2. **转发消息显示**
   ```
   ↪️ 转发自 李四 在房间 room123:
   原消息内容...
   ```

### 消息编辑

1. **编辑自己的消息**
   - 鼠标悬停在自己的消息上，点击 ✏️ 编辑按钮
   - 输入框进入编辑模式（显示编辑状态），修改后回车发送
   - 按 Esc 键可随时取消编辑

2. **编辑后的消息**
   - 消息位置不变，末尾追加灰色的"已编辑"标记（不会破坏时间戳显示）
   - 其他成员实时看到新内容

### 📎 文件传输（真实 P2P 直传）

1. **发送文件**
   - 点击"发送文件"选择文件（单文件最大 **200MB**）
   - 房间内其他成员会收到接受/拒绝提示

2. **传输机制（关键点）**
   - 接受后走 **WebRTC DataChannel 点对点直传，文件内容不经过服务器**
   - 按 64KB 分块发送，利用 `bufferedAmount` 背压控制防止内存爆涨
   - 双方都显示**真实进度条**（按 transferId 区分多个并行传输）
   - 接收完成后出现"💾 保存"按钮，点击即可保存到本地
   - 拒绝接收时发送方立即看到"已拒绝"状态

### 🖼️ 图片消息与历史恢复

1. **发送图片**：图片以 DataURL 经服务器中转，房间成员实时收到
2. **历史恢复（关键点）**：服务器在内存中缓存最近 **50 张 / 1 小时内**的图片；
   刷新页面加载聊天历史时，图片消息自动向服务器请求原始数据恢复显示
3. **过期提示**：超过时限或被挤出缓存的图片显示"🖼️ 图片已过期"，文字记录保留

> ⚠️ 图片缓存只存于内存：服务器重启后历史图片无法恢复（文字记录持久化在 `data/chat-history.json`，不受影响）。

## 🎛️ 高级配置

### 管理员配置 (`server/app.js`)

实际代码中的配置（与 `ADMIN_CONFIG` 常量一一对应）：

```javascript
const ADMIN_CONFIG = {
  password: "admin123",        // 管理员密码（部署前必须修改！）
  allowedIPs: ["127.0.0.1", "::1", "localhost"],  // 允许登录的IP白名单
  secretKey: "webRTC_admin_secret_2024",          // 令牌签名密钥（部署前建议修改）
  sessionDuration: 30 * 60 * 1000,                // 会话时长（30分钟）
  features: ["clear-room", "delete-message", "view-logs", "view-devices"]
};
```

**认证机制（关键点）**：
- 登录时校验 **密码 + IP 白名单** 双重条件，任一不符即拒绝
- 登录成功后下发 HMAC-SHA256 签名的令牌，有效期 `sessionDuration`，过期自动清除
- 清除房间、查看日志等敏感操作都必须携带令牌，伪造令牌会被拒绝并记入管理日志

> ⚠️ **服务器部署注意**：`allowedIPs` 默认只允许本机登录。部署到云服务器后，你在自己电脑上
> 打开管理面板会被拒绝 —— 需把你的公网 IP 加入白名单，或临时改为 `["*"]`。

### 🚢 单端口架构（部署关键点）

页面、Socket.IO 信令、PeerJS 信令统一走 **3000 端口**（PeerJS 挂载在 `/peerjs` 路径），
反代/防火墙/隧道只需处理一个端口。实现要点：

- `ExpressPeerServer` 会接管所在 HTTP 服务上的**所有** WebSocket upgrade 事件，与 Socket.IO 冲突
- 服务端给 PeerJS 挂了一个**不监听端口**的内部 HTTP 服务，由主服务器按路径把 `/peerjs` 的
  upgrade 请求转发过去，两条信令通道互不干扰
- 客户端按页面地址**同源自动适配** PeerJS 连接（旧配置里残留的 `peerPort: "9000"` 会自动迁移）

### 安全建议

1. **修改默认密码**
   - 首次使用前修改管理员密码
   - 使用强密码（至少12位，包含大小写字母、数字、特殊字符）

2. **限制IP访问**
   - 将 `allowedIps` 设置为具体IP地址
   - 不要使用 `"*"` 允许所有IP

3. **定期备份数据**
   - 每天备份 `data/` 目录
   - 保留多个时间点的备份

4. **监控管理员日志**
   - 定期检查 `admin-logs.json`
   - 关注异常登录和操作

## 🐛 故障排除

### 常见问题

#### 1. WhatsApp分享功能无法使用
**问题**：点击WhatsApp按钮没有反应

**解决方案**：
- 确保已加入房间
- 检查是否已设置WhatsApp信息
- 刷新页面重新登录

#### 2. 管理员登录失败
**问题**：输入正确密码但仍提示登录失败

**解决方案**：
- 检查IP地址是否在允许列表中
- 确认密码大小写是否正确
- 检查管理员配置是否正确

#### 3. 消息删除失败
**问题**：点击删除按钮后消息仍存在

**解决方案**：
- 确认是否是自己的消息
- 检查网络连接
- 刷新页面查看消息状态

#### 4. 数据丢失
**问题**：服务器重启后数据消失

**解决方案**：
- 检查 `data/` 目录权限
- 确认文件写入权限
- 从备份恢复数据
